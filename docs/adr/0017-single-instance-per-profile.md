# ADR-0017：每个 Profile 只允许运行一个 Bridge 实例

- 状态：Accepted
- 日期：2026-07-31
- Supersedes：ADR-0004 中未限制同 Profile 多实例的部分

## 背景

Bridge 允许不同 profile 在同一台机器上并行运行，但同一 profile 的两个进程会
连接同一个飞书应用、读写同一组 session 文件。消息和卡片回调可能被不同进程
消费，而模型选择 nonce、ask broker、在途 run 等状态只存在于创建它们的进程
内存中，最终导致回调失效或状态互相覆盖。

ADR-0004 的进程注册表以 PID 为键，只负责 dashboard 观测和心跳，不提供启动
互斥，因此无法阻止上述情况。

## 决策

1. `run --profile <name>` 在读取 profile 配置、访问飞书 API 或创建 Bridge 前，
   必须先获取该 profile 的进程级排他锁。
2. 锁文件固定为 `profiles/<profile>/bridge.lock`。进程通过操作系统的非阻塞
   `flock` 持有锁；文件内容记录当前 PID，供冲突错误提示使用。
3. 锁已被占用时启动立即失败，不接管、不终止已有进程。
4. 锁由打开的文件描述符持有直至进程退出；正常退出显式解锁，崩溃或强杀时由
   操作系统自动释放。锁文件本身可以保留，不把文件存在与否当成占用依据。
5. 不同 profile 使用不同锁文件，仍可并行运行。进程注册表继续承担 dashboard
   展示职责，不参与互斥判断。

## 后果

- 同一 profile 的消息、卡片回调和内存态始终由唯一 Bridge 进程处理。
- 重复启动会明确返回已有进程 PID，操作者可以自行决定是否停止旧实例。
- 从不持锁的旧版本升级时，需要先停止旧实例再启动新版本；新版本之间无需处理
  陈旧 PID 文件。
