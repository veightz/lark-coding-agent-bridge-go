# ADR-0006: 私聊任务自动建群（p2p → group 升级）

- 状态: accepted
- 日期: 2026-07-26
- > 长度兜底规则已被 [ADR-0009](0009-stricter-p2p-task-classification.md) 取代（仅附件/动作关键词算任务）

## 背景（Context）

用户与机器人私聊时，Go 版原先直接在私聊 scope 里运行任务。用户希望
私聊成为「任务入口」：发出明确任务时自动建一个专属群，私聊里收到
一张带**一键跳转群会话**按钮的卡片，且任务在群里**自动启动**——
不需要进群后再把诉求重述一遍。群里可以继续 @ 机器人迭代，私聊则
保持轻量（闲聊、快速问答不建群）。

原版 TS 只有显式命令 `/new chat [name]`，没有语义级自动升级。

## 选项（Options）

1. 每条私聊都建群 — 打扰用户，群列表爆炸，闲聊没法用。
2. 卡片按钮让用户选「拉群/私聊」— 确定性高，但多一次点击，
   违背「不需要我再表达诉求」的目标。
3. 启发式语义判断：明确任务自动建群，闲聊留在私聊。

## 决策（Decision）

选 3，并保留显式命令兜底：

- **判定**：`LooksLikeTask(content, hasResources)`（`classify.go`）——
  纯启发式：带附件即任务；完全匹配的闲聊短句（你好/在吗/谢谢…）不建群；
  命中动作关键词（帮我/修复/实现/分析/fix/implement/…）即任务。
  ~~≥20 字长消息兜底~~ 已由 ADR-0009 取消（误建群代价过高）。
- **升级流程**（`group.go`）：建群（bot 为群主，拉用户，`im:chat` 权限）
  → 私聊发跳转卡片（CardKit 按钮 `open_url` 行为，
  `https://applink.feishu.cn/client/chat/open?openChatId=<id>`）
  → 群里发欢迎 + 任务上下文 → 原消息改写 ChatID 后 push 进群 scope
  的去抖队列，走正常 runBatch 自动启动。
- **跟发合并**：建群后 15s 窗口期内同一私聊的后续消息视为同一任务
  的一部分，转入同一个群（`escalations` 表 + `done` channel 等待
  建群结果），避免连发两条消息建两个群。
- **例外**：私聊 scope 被 `/bind` 显式绑定到 CLI 会话时尊重绑定，
  不升级；建群失败（缺权限等）降级为私聊直接处理并提示，不丢消息。
- **显式兜底**：`/new chat [name]` 命令随时可手动建群（对齐原版）。

## 理由（Rationale）

- 自动化是用户明确要求；启发式比 LLM 判定零延迟、零成本、可测试，
  误判代价可控（误判为任务 → 多个群；误判为闲聊 → 私聊里回答）。
- 升级在去抖队列**之前**改写 scope，连发消息自然合并进同一批 run。
- 跳转卡片用 applink 而非群链接分享，无需额外权限、一键直达。

## 后果（Consequences）

- 群名取任务文本前 20 字（截断加省略号），语义化但可能撞名，
  靠创建时间区分。
- 15s 窗口是启发式参数，后续可按体验调整；窗口过期后新任务建新群。
- 建群需要应用有 `im:chat` 权限；缺失时流程降级但任务不丢。
- 快捷回复（quick_reply）p2p 提示改用 `SendDirectText`
  （receive_id_type=open_id），修复了此前把 open_id 当 chat_id
  发送导致 230001 invalid receive_id 的问题。
