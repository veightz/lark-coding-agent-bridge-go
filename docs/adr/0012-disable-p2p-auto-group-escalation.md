# ADR-0012: 取消私聊任务自动建群（统一话题回复）

- 状态: accepted
- 日期: 2026-07-28
- Supersedes: ADR-0006 中的「私聊明确任务自动建群」路径；ADR-0009 的判定规则随之失效
- 不 supersede: `/new chat` 显式建群、`/open` 复用/新建群（ADR-0007）

## 背景（Context）

ADR-0006 在私聊识别到「明确任务」后自动建群，把进度挪到群里，是为了避免
长回复刷屏私聊主时间线。

此后私聊已改为：

1. **话题回复**：`reply_in_thread` 以用户原消息为根开话题（主时间线干净）；
2. **按话题隔离会话**（ADR-0010）：主时间线每条消息新 scope，话题内续聊。

在「已通过话题回复」的前提下，再对任务消息自动建群会产生**重复组织**：

- 用户在私聊发任务 → 既开话题又建群 + 跳转卡；
- 任务实际在群里跑，话题下却空或只有跳转卡，心智分裂；
- 误判任务意图时仍会多出一个无关群（ADR-0009 只能收紧，无法消除）。

用户反馈：已经话题回复了，不要再自动建群。

## 选项（Options）

1. 保留自动建群 + 话题回复 — 继续双重路径，体验重复。
2. 仅话题内续聊时跳过建群，主时间线任务仍建群 — 半吊子，主时间线仍会「惊喜建群」。
3. **取消自动建群**：私聊一律话题内处理；需要群时用 `/new chat` / `/open`。

## 决策（Decision）

选 3：

1. `HandleMessage` **不再**调用 `escalateP2P` / `LooksLikeTask`。
2. 删除自动升级状态机（`escalation` / 15s 跟发窗口 / `pushToGroup`）。
3. 保留显式建群与跳转：`/new chat [名称]`、`/open <id>`、`sendGroupJumpCardEx`、`groupNameFor`。
4. `LooksLikeTask` 与 ADR-0009 判定规则退役（无调用方）。

## 理由（Rationale）

- 话题回复已解决 ADR-0006 的主因（主时间线刷屏），自动建群边际收益为负。
- 显式命令路径保留「要群就建群」能力，不剥夺协作场景。
- 删除启发式升级后，私聊行为可预测：发什么都在话题里答。

## 后果（Consequences）

- 私聊任务不再自动出现「新群 + 跳转卡」；用户需 `/new chat` 或 `/open` 才进群。
- 原依赖「发任务就进群」的习惯需要改用命令（与 botmux / 显式协作模型更接近）。
- 文档：`design.html` §10、`implementation.html` §4.6 改为描述「已取消自动升级」。
